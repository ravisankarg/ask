Smart by design

Every module knows what not to do.

Good local intelligence comes from disciplined boundaries: each module handles its own uncertainty and passes a clean contract forward.

01 · MEMORY

Incremental preparation

Discovers only new phone records, resumes interrupted work, and appends to the right indexes without erasing previous knowledge.

Smart move · unchanged records stay untouched
02 · PLANNER

Meaning before matching

Separates content such as “sunset” from people, places, document types, requested fields, and conversational references.

Smart move · validates the plan before retrieval
03 · RETRIEVAL

Source-aware search

Visual memories can match by meaning and metadata; written records require semantic relevance plus same-record lexical proof.

Smart move · one rule does not weaken every source
04 · FUSION

One honest result order

Independent candidate streams are scoped, scored, deduplicated, and merged before the user or answer layer sees them.

Smart move · answer evidence comes from that same order
05 · EVIDENCE

Layout-preserving context

Photos stay visual, document pages retain columns and tables, while calls and messages keep their precise native text.

Smart move · evidence format follows the record
06 · ANSWER GUARD

Field-aware verification

Numbers and dates must stay attached to the requested label, preventing a nearby identifier or timestamp from becoming the answer.

Smart move · uncertainty becomes refusal, not invention
07 · EXPERIENCE

Visible state and control

Users see preparation, query-plan, search, and answer progress—and can pause background indexing to search immediately.

Smart move · useful before preparation is complete

Trust boundaries

Privacy is not a final step.

It shapes ingestion, indexing, planning, retrieval, evidence, and the answer itself.

On-device by default

Personal records and their searchable representations stay under the user’s control.

Hard scope before relevance

People, place, time, media, source, and exclusions are enforced rather than suggested.

Inspectable failures

If a query plan is rejected, its actual output and validation reason are visible.

No hidden evidence swap

The answer receives a bounded window derived from the same ranked results shown to the user.
