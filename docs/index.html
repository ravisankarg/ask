High-level modules

Each boundary has a job.

Inputs and outputs stay explicit so the system can evolve without hiding decisions inside a single retrieval or generation step.

01

Source ingestion

Input: personal records and source metadata

Output: stable records, signatures, and ownership

02

Preparation

Input: new or changed records

Output: searchable text, metadata, identities, representations, and checkpoints

03

Query understanding

Input: user language

Output: intent and structured constraints

04

Retrieval

Input: constraints and source indexes

Output: candidates with comparable scores

05

Fusion and scope

Input: candidate lists and exclusions

Output: one trustworthy cross-source order

06

Evidence and answer

Input: question and bounded top records

Output: concise answer with validated facts

07

Product surface

Input: progress, timings, results, and answer events

Output: browseable, explainable interaction

Design boundaries

Trust is a pipeline property.

Hard scope first

Person, place, time, source, media type, and exclusions constrain retrieval before relevance expansion.

One visible order

The result grid and answer evidence originate from the same merged ranking, with stale records removed.

Labels stay attached

A requested field is resolved through its own label, so nearby dates or numbers cannot silently replace it.

Local by default

Personal records, query processing, retrieval, and answer generation remain on the device.
