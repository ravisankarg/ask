Search is the product. The answer is a layer on top.

The user always gets the newest 200 matching photos in one smooth grid. A separate Context Picker privately distills at most 16 images for Gemma—never replacing the results the user can browse.

Query + answer flow

Inspectable before it is intelligent.

Deterministic and Gemma planning converge on one execution language. The corrected plan becomes visible before retrieval starts.

1

Understand + correct

Resolve spelling against known people, query vocabulary, locations, dates, MIME, negation, and event phrases.

2

Compile the QP spec

Emit the canonical C-like AST and show it below the search bar immediately.

3

Execute exact set logic

Combine TurboQuant semantics with SQLite person, OCR, date, place, and MIME branches.

4

Publish results first

Render up to 200 newest matches in the sole vertical scroller while context work continues.

5

Distill answer context

Join episode membership and choose no more than 16 complementary images plus needed metadata.

6

Answer naturally

Use a clean Gemma conversation for a grounded 2–3 sentence answer and interesting follow-ups.

Context Picker

Maximum coverage.
Minimum repetition.

The search ranking finds relevance. The persisted episode index supplies event structure. The Context Picker balances both with visual, OCR, people, place, metadata, and timeline novelty—without doing expensive clustering at query time.

pick(x) = relevance + coverage + novelty − duplicate cost
  • ✓Episode-first coverage chooses the best retrieved member from distinct events.
  • ✓Modality-aware novelty rewards new scenes, OCR, people, places, and dates.
  • ✓Query-aware fields keep irrelevant OCR and metadata out of the prompt.
  • ✓Strict budget stops at 16 images, regardless of result count.
